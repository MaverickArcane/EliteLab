# EliteLab 0.6.0

Release cleanup adds [cargo selling](../CARGO-SELLING.md), a separate Carrier ops
workspace with [group mining through PTN unloading](../GROUP-MINING.md), Overview credit history, shield
state, smaller [layout choices](../WORKSPACES.md), provider attribution and the
[Materials GIF guide](../MATERIALS-GUIDE.md). The security, PTN and partial-grade
fixes are recorded in [the execution plan](../NEXT-RELEASE-PLAN.md).
This remains a candidate; live multiplayer, mining rewards, bio tracking and
unperformed platform checks must not be inferred from offline regression results.

EliteLab 0.6.0 adds desktop installers, journal history, a mining desk, and
expanded trading and materials planning. Windows and macOS packages include
Python. Debian/Ubuntu installs its runtime and desktop dependencies through the
package manager. Source installs still use Python 3.10 or newer and the standard
library.

These notes describe the candidate build. Release publication follows the
maintainer checks in [the release procedure](https://github.com/MaverickArcane/EliteLab/blob/v0.6.0/docs/RELEASE-PACKAGES.md).

## Download and start

| Download | Use |
| --- | --- |
| `EliteLab-Setup-x64.exe` | Windows x64 installer. After installation, open **Start > EliteLab**. |
| `elitelab_0.6.0_all.deb` | Debian/Ubuntu package. Open **EliteLab** from the applications menu. |
| `EliteLab-0.6.0-macos-arm64.pkg` | Apple Silicon Mac installer. Open **Applications > EliteLab**. |
| `EliteLab-0.6.0-macos-x86_64.pkg` | Intel Mac installer. Open **Applications > EliteLab**. |
| `EliteLab-v0.6.0-source.tar.gz` | Source archive for Python 3.10+, custom deployments and development. |

Every download has a matching `.sha256` file. Installers are unsigned. The Mac
app has an ad-hoc integrity signature, without Developer ID or notarization;
follow the [macOS first-open guidance](https://github.com/MaverickArcane/EliteLab/blob/v0.6.0/README.md#macos-installer) for a trusted download.

The Windows tray, Linux indicator/control window and Mac menu bar can open
dashboard/setup, opt in to login startup, and Quit. Windows may place the icon
under the notification area's hidden-icons arrow. Chromium-family browsers use
a dedicated app window; other default browsers open a tab. Closing that window
does not stop the app. First launch opens setup to select the journal folder.
On Mac, select a synced or copied journal folder.

Windows setup lets you choose an installed Chrome, Edge, Brave or Chromium to
power the standalone app window. Upgrades retain the choice; rerun setup to
change it. Guest mode is the default and keeps browser accounts separate, but
browser-only layout/filter preferences reset when all guest windows close.
Persistent mode remembers those preferences and can use browser sign-in/import
features. EliteLab saved data and plans remain in either mode.

## What changed

- Desktop packaging, persistent setup, restart handling, optional login startup,
  and per-user data directories across platforms.
- Journal history indexed locally in SQLite, with commander-specific credit
  snapshots, merit cycles and material collection evidence.
- Mining ring/hotspot discovery, prospector composition, refinery output,
  buyer comparisons, recorded sales, profit attribution and observed merits.
- Trading route comparison, selected-leg progress, current-stop market evidence,
  rare sell targets and handoff to Powerplay searches.
- A shared materials/recipe planning workflow, saved quantities, ingredient
  previews, sourcing, synthesis and expedition tools.
- Expanded HTTP/MCP tools and prompts, browser security checks, and desktop/mobile
  regression coverage.

Mining sale associations and conditional merit estimates remain estimates.
Real-game validation of mixed cargo, transfers/ejection and mining merit
eligibility remains tracked in #3. Frontier Companion API access is not included;
#6 awaits an approved EliteLab developer application and live validation.

## Upgrade and remove

Quit the running app before installing an update. Upgrade in place with the
installer for your platform. Preserve your existing settings and data when
moving from a source checkout: select the old data folder in setup, or copy it
to the new default before using the new installation.

| Platform | Default settings | Default app data |
| --- | --- | --- |
| Windows | `%APPDATA%\EliteLab\settings.json` | `%LOCALAPPDATA%\EliteLab\data` |
| Debian/Ubuntu | `~/.config/elitelab/settings.json` | `~/.local/share/elitelab` |
| macOS | `~/.config/elitelab/settings.json` | `~/Library/Application Support/EliteLab` |

Configured paths and the documented XDG overrides take precedence. Existing
Windows portable bundles with a `data` folder beside the app continue using it.
Uninstall preserves personal settings and saved data. On Mac, turn off login
startup before moving the app to Trash; Linux login preferences remain dormant
while the executable is absent. Windows uninstall removes only its own startup
entry.

## Validation

CI checks Python 3.10/3.13 on Windows and Linux, browser workflows, source setup
on macOS, Docker, and package installation/upgrade/removal. Packaged runtime
checks use fixture journals and no system Python on PATH where Python is bundled.
Native desktop checks exercise tray/menu actions and preserve user-data sentinels.
Real browser windows, login cycles and downloaded-file OS prompts are additional
manual release checks; automated results do not establish in-game reward rules.
