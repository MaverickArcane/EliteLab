# EliteLab 0.6.0 Beta 4

One transparent activity HUD now follows your work across EliteLab. Open it from
the dashboard header or a panel's HUD button, choose a view, and pin it above a
windowed or borderless game. This beta also includes the reviewed Rhino cargo,
grouped-location, Materials replay, slow-start and PTN held-stock advert changes.
It retains Beta 3's security fixes and isolated staging tools.

## Activity HUD

- Choose among 28 views across flight, mining, trading, Powerplay, engineering
  and missions. Each uses the existing local module data.
- Use a borderless, transparent background with outlined controls, softer text,
  pinning, opacity and click-through locking. Reopening the shortcut recovers the
  existing HUD instead of creating another window.
- `Ctrl+Alt+H` hides/shows, `Ctrl+Alt+L` locks/unlocks clicks, and `Ctrl+Alt+R`
  shows, pins and unlocks the HUD. The activity menu also provides these controls.
- Rhino automatic shows a prominent bearing and compass on approach, then
  deployment progress nearby. Once arrival is observed, quiet GPS reports while
  rigs process no longer switch progress back to navigation or waiting.
- Offline or stale information is qualified or paused. No rig hopper, extraction
  rate, replenishment or asteroid coordinates are invented.

Native transparency is Windows-only. The Rhino browser overlay remains available
in browsers supporting Document Picture-in-Picture. A desktop installer registers
the dashboard's Open HUD link; portable users can use `EliteLab HUD.vbs`.

## Other changes

- Group Rhino deposits by system, body and PML while preserving individual
  coordinates, confirmation and depletion reports. Circuit rig totals remain
  separate from per-deposit observations; unmapped deposits stay explicit.
- Keep Rhino/ship holds accurate through transfers and automatic boarding
  unloads. Show system distance and estimated jumps before surface directions.
- Publish Materials inventory and session gains together after journal replay,
  preventing historical counters from flashing during reconstruction.
- Keep the app-window request pending through slow startup. Cancellation and
  shutdown still prevent a late window from opening.
- Prepare direct-sale or unloading adverts from carrier stock and entered sale
  terms. Optional buyer reports suggest a price after a chosen hauler margin.
  Unknown stock, report age and estimates remain explicit. Nothing is posted to
  Discord and no game order is placed automatically.

## Update and validation

Exit EliteLab from its tray menu and close the HUD before installing. Setup
refuses to replace a running instance or HUD. Run the Beta 4 installer over the
existing installation; saved settings and data are retained. Portable staging
profiles remain separate. Game journals are not modified.

The candidate is reviewed in PRs #135–#140 and the Beta 4 integration PR. Local
browser checks cover synthetic desktop/narrow layouts, live updates, PiP,
grouped deposits and PTN adverts. Native HWND checks cover all 28 activities,
transparency, pinning, click-through lock, recovery and reopening. The release
workflow requires the full CI matrix and native package lifecycle checks before
publication, then verifies every package checksum. Review findings and test
evidence are posted on the PRs.

Mapped asteroid orientation remains research for a future PR. Game foreground
legibility, downloaded macOS Gatekeeper behavior and a real host-plus-two-friends
session remain player acceptance checks. Report problems with the exact beta,
platform, reproduction steps and a redacted diagnostic ZIP; omit credentials,
settings files and journals.
